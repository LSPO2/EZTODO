# EZTODO 开发目标与路线图

## 目标 0：建立可信基线

交付：

- 388 条 P0 明细与摘要自动一致；
- 12 条 DoD 发布门禁；
- 每次验证记录环境、命令、结果、日期和证据路径。

退出条件：

- 矩阵汇总漂移会使 CI 失败；
- “已实现”不会被错误表述为“已验收”。

## 目标 1：完成本地 Todo 数据安全闭环

范围：

- CRUD、父子任务、批量、回收站、导入导出；
- 所有复合操作事务化；
- 重启持久化、迁移失败只读保护、升级前备份；
- outbox 与任务写入保持原子一致。

退出条件：

- 自动化故障注入无部分写入；
- Tauri 重启后数据一致；
- 删除/恢复 3 层任务树完整；
- 10,000 条任务性能门槛通过。

## 目标 2：完成 AI 辅助添加

已完成的本轮子目标：

- 设置导航和 OpenAI 兼容配置；
- API Base、模型、服务商保存；
- API Key 会话内存保存；
- Tauri 原生 HTTPS 请求，避免 WebView CORS；
- 连接测试；
- 严格 JSON 解析、字段归一化、20 项/3 层限制；
- 可编辑确认卡；
- 用户确认后才创建，失败不静默降级。

下一步：

- `AICaptureService` 单事务写入任务树、提醒、重复、标签和 outbox；
- 创建后撤销；
- Windows 凭据管理器；
- server-proxy/BYOK 双模式；
- 真实 DeepSeek/OpenAI 兼容服务验收。

退出条件：

- 三条核心语料能正确创建日期、提醒、重复和父子任务；
- 无 Key、错误 Key、超时、429、非 JSON、超过限制均不会写库；
- 第 N 项写入失败时整体回滚；
- Key 不出现在数据库、日志、导出和崩溃报告中。

## 目标 3：完成账号和多设备同步

范围：

- 登录、Token 刷新/撤销、安全存储；
- 设备注册；
- push/pull、幂等、游标、墓碑和冲突；
- 离线自动重试和可见同步状态。

退出条件：

- 两设备离线交叉编辑后收敛；
- 重放请求不产生重复任务；
- 同步失败不会丢本地修改。

## 目标 4：完成提醒与 Windows 外壳

范围：

- 任务全生命周期重新调度；
- 多提醒、稍后提醒、错过提醒和安静时段；
- 托盘、睡眠恢复、通知点击导航；
- 单实例、多屏、DPI、快捷键。

退出条件：

- 固定 Windows 真机清单全部通过；
- 重复任务月末、闰年、时区变化测试通过；
- 主窗口隐藏后通知仍工作。

## 目标 5：完成发布与恢复

范围：

- 客户端/服务端数据库备份恢复；
- 安装、升级、卸载；
- 签名更新、失败回滚；
- 发布包安全扫描。

退出条件：

- 客户端 SQLite 和服务端 PostgreSQL 均完成恢复演练；
- 旧版本带数据升级成功，失败时能安全回退；
- 12 条 DoD 全部具备证据。

## 目标 6：架构收敛

范围：

- 拆分 `App.tsx`；
- 统一 AI/任务/同步协议；
- 移除重复旧组件和乱码；
- ESLint warning 清零；
- 建立最小 E2E 套件。

退出条件：

- 页面、业务服务、Repository 边界清晰；
- 新功能不再向主应用文件堆叠业务逻辑；
- 全部门禁无 error、无 warning。
