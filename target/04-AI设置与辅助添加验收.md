# AI 设置与辅助添加验收记录

日期：2026-07-24

## 本轮交付

### 设置栏

- 左侧导航新增“设置”。
- 支持填写服务商名称、API Base、模型和 API Key。
- API Base 和模型通过现有 Settings Repository 持久化。
- API Key 只保留在当前应用内存，不写入设置表、SQLite、localStorage 或日志。
- 支持“保存设置”和“测试连接”。

### AI 解析

- 支持 OpenAI 兼容 `/chat/completions`。
- Tauri 环境通过 Rust 原生 `reqwest` 请求，避免 WebView CORS。
- 远程服务强制 HTTPS；仅 localhost、127.0.0.1、::1 允许 HTTP。
- 禁止自动跟随重定向，降低 Authorization 泄露风险。
- 对 401/403、429、其他 HTTP 错误和无内容响应给出可见错误。
- 响应按严格 JSON 结构校验，并兼容 snake_case/camelCase 字段。
- 单次最多 20 个任务、最多 3 层。

### 确认后创建

- AI 结果先显示确认区。
- 用户可修改标题、优先级和计划日期。
- 显示整体置信度、警告和子任务摘要。
- 用户明确点击“确认创建”后才写入。
- 防止确认按钮重复点击。
- API 失败不再静默伪装成 AI 成功，也不会自动写任务。

## 手工验收步骤

1. 启动 Tauri 应用，打开“设置”。
2. 填写服务商、API Base、模型和测试 Key，点击“测试连接”。
3. 确认连接成功；退出重启后确认 Key 输入框为空。
4. 输入“明天下午三点交实验报告”，检查日期、标题和置信度。
5. 修改确认区标题，点击确认，重启应用确认任务仍存在。
6. 使用错误 Key、无额度 Key 和本机不可达地址，确认只显示错误、不创建任务。
7. 检查 SQLite、localStorage、日志和导出文件，确认没有测试 Key。

只有上述真机步骤通过后，才能把本功能状态从“已接线/自动化验证”提升为“真机已验证”。
