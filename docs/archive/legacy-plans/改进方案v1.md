# EZTODO 改进方案 v1

> 文档版本：v1.0  
> 编制日期：2026-07-22  
> 适用范围：Windows PC MVP（Tauri + React + FastAPI）  
> 优先级规则：P0 为发布阻断项；未通过 P0 验收，不得标记为“完成”或发布 MVP。

---

## 1. 目标与结论

本方案用于把当前的“浏览器演示页面 + 多个未接线模块”收敛为可验收的 PC 端 AI Todo MVP。首要目标不是继续增加页面，而是建立一条真实、唯一、可测试的数据与功能链路：

```text
React UI
  -> Store / Service
  -> Repository
  -> Tauri SQLite（离线真源）
  -> 同步 Outbox
  -> FastAPI 同步 API / AI API
  -> PostgreSQL（服务端真源与事件日志）
```

当前项目具备 Tauri、SQLite migration、Repository、同步、提醒、AI Provider、FastAPI 等代码基础，但运行入口 `apps/desktop/src/App.tsx` 仍直接使用 React state 与 `localStorage`。因此，已有模块不能视为用户已可使用的功能。本方案以“先打通，再补全，再验证”为执行顺序。

### 1.1 当前基线

- 前端生产构建与 TypeScript 检查通过；前端 Vitest 40 项纯模块测试通过。
- ESLint 当前失败：配置引用的 `typescript-eslint` 未在 `apps/desktop/package.json` 中声明。
- 后端 AI 测试 18 项中有 3 项失败，涉及子任务拆分、模糊提醒置信度与过去日期告警。
- Tauri 打包尚未完成验证；当前机器未安装 Rust/Cargo，且 Tauri 配置引用的图标文件不存在。
- 当前工作区已有未提交的 `apps/desktop/src/App.tsx` 修改；执行本方案前必须先决定其保留、重构或拆分策略，禁止在不确认的情况下覆盖它。

### 1.2 MVP 范围

MVP 必须完成：离线任务管理、父子任务、项目和标签、时间/重复/提醒、回收站、导入导出备份、账号登录、增量同步、AI 自然语言建任务、Windows 托盘与打包。

MVP 不包含：多人协作、甘特图、番茄钟、Google/Outlook 双向同步、浏览器扩展、公开 API、iOS/macOS/Linux 客户端。Android 只保留协议与平台抽象，不交付客户端。

## 2. 必须先冻结的工程规定

以下规定从 P0-0 开始执行。违反任一规定的改动不得合并到发布分支。

### 2.1 单一数据源规定

1. 生产版任务数据只能通过 `Repository -> Tauri SQLite` 读写；UI 不得直接读写 SQL，也不得直接读写 `localStorage`。
2. `localStorage` 仅可作为浏览器演示或单元测试适配器，必须显式标注 `demo/test only`，不得在 Tauri 正常运行时静默降级。
3. 任意任务创建、编辑、完成、删除、恢复、父子联动、批量操作，必须在同一数据库事务中完成业务写入和 `sync_outbox` 写入。
4. 本地 SQLite 是离线操作的立即真源；网络不可用时不得阻塞创建、编辑、完成或删除。
5. 服务端同步成功后才更新 outbox 的 `synced_at`。超时或响应丢失时保留原操作并以同一 `operation_id` 重试。

### 2.2 数据协议规定

1. 任务、提醒、重复规则、同步操作、AI 输入输出必须以 `packages/contracts` 为唯一语义来源。
2. TypeScript 与 Python 之间允许代码生成或分别实现，但必须建立同一份 JSON Schema 和契约测试；禁止长期维护 snake_case、camelCase、字段缺失的三套模型。
3. 所有实体 ID 使用 UUIDv7 或等价的可排序客户端生成 ID；禁止使用 `Date.now()` 作为任务 ID。
4. 精确时间传输使用 UTC ISO 8601；同时保存 IANA 时区。全天任务只使用独立日期字段，不使用 UTC 零点代替。
5. 任务层级最多 3 级。移动任务前必须防止循环引用和越级；数据库、Repository、服务端三层都要校验。

### 2.3 发布质量规定

1. `npm ci`、lint、类型检查、前端测试、后端测试、构建、契约测试必须在 CI 中运行。
2. “代码文件存在”不构成完成证据。每个 P0 功能必须至少有：需求 ID、实现位置、自动化测试、手工验收记录、失败处理说明。
3. `PROJECT_SUMMARY.md`、阶段计划和发布清单必须由同一份验收矩阵驱动；未通过的项不得标记为完成。
4. 生产环境禁止使用默认密码、占位 JWT Secret、占位 API Key、公开 PostgreSQL 端口或纯 HTTP 外部访问。

- 阶段总结不得再使用“已完成”替代验收证据。

## P0-1：收敛客户端架构与本地数据库

### 目标

将生产运行时从 `App.tsx -> localStorage` 切换到 `AppLayout -> Store -> Repository -> SQLite`，并保证离线数据可靠。

### 执行步骤

1. 以 `components/layout/AppLayout` 为应用根布局，接入 Sidebar、Toolbar、TaskList、TaskDetail、DataPage、AIQuickAdd 等组件；路由或页面状态只保留在 Store 中。
2. `App.tsx` 仅负责初始化与组装，不得包含任务持久化、CSV 拼接、AI 关键词解析、备份恢复等领域逻辑。
3. 所有任务读写统一调用 `TaskRepository`；项目、标签、提醒分别调用对应 Repository。Store 仅管理加载状态、筛选状态、选中项和异步命令，不直接拼接 SQL。
4. 删除生产路径中对 `eztodo_db` 的直接 `localStorage` 访问。浏览器适配器如保留，必须：
   - 不得在初始化时覆盖已有数据；
   - 正确执行 `WHERE`、`UPDATE`、事务和约束，或在不支持时明确失败；
   - 只能由测试或独立 demo 入口调用。
5. 启动 SQLite 时执行：`foreign_keys=ON`、WAL、合理 `busy_timeout`、版本化迁移、迁移前备份、迁移失败只读保护与可恢复提示。
6. 将客户端 migration 拆分为可审查文件或严格版本列表。新增 migration 只能追加，禁止编辑已发布版本。
7. 任务创建时生成 UUIDv7，并同时写入 `tasks`、`task_events`、`sync_outbox`；操作 ID 与实体 ID 分离。
8. 补齐并统一任务字段：`parent_id`、`project_id`、`note`、`priority`、`sort_order`、`scheduled_date`、`scheduled_at`、`due_at`、`is_all_day`、`timezone`、`estimated_minutes`、`deleted_at`、`revision`、`source`、`source_capture_id`。

### 关键规则

- 标题保存前 `trim`，空标题拒绝保存；建议标题上限 200 字符、备注上限 10,000 字符，超出时给出明确提示。
- `source` 枚举必须与所有写入方一致；若重复实例使用 `recurrence`，迁移中的 CHECK 约束必须先支持该值。
- 父子删除、恢复、完成联动必须通过递归查询或明确的三层限制实现，禁止只处理一层子任务。
- 批量操作必须有一个批次 ID，以支持一次撤销和同步追踪。

### 验收标准

- 在 Tauri 下创建、重启、编辑、删除、恢复任务后，数据仍来自 SQLite，不依赖浏览器存储。
- 断网创建任务后，存在对应 outbox 记录；恢复网络前任务不丢失。
- 数据库迁移、迁移前备份、迁移失败恢复各有自动化或可复现手工测试。

## P0-2：补齐本地 Todo 功能与父子任务规则

### 目标

先完成不依赖网络的完整 Todo 体验，再接入同步和 AI。

### 执行步骤

1. 实现 Inbox、今天、未来 7 天、已逾期、无日期、已完成、回收站视图；每个视图的过滤条件由 Repository 查询实现，不在组件中重复判断。
2. 完成标题、备注、优先级、项目、标签、计划日期、计划时间、截止时间、全天、时区的编辑界面与校验。
3. 实现搜索标题和备注，按项目、标签、优先级、状态筛选，按计划时间、截止时间、创建时间、手动排序排序；界面必须显示当前生效筛选条件。
4. 实现复制、移动项目、标签编辑、拖拽同级排序、多选、批量完成/恢复/删除/移动/标签/优先级，以及立即撤销。
5. 实现父子任务：新建子任务、缩进/提升、折叠/展开、`3/5` 进度。
6. 完成规则必须固定为：
   - 子任务全部完成时自动完成父任务；
   - 父任务仍有未完成子任务时，完成父任务必须弹窗；
   - 弹窗提供“仅完成父任务”和“同时完成所有子任务”；
   - 重新打开父任务时让用户选择是否恢复子任务；
   - 删除父任务时所有子任务进入回收站，恢复父任务时完整恢复；
   - 子任务截止时间晚于父任务时只警告，不阻塞。
7. 对 10,000 条任务建立固定数据集、查询基准与 UI 性能测试。目标为搜索结果 P95 在 200 ms 内出现；测试机器和数据分布必须记录。

### 验收标准

- 父子循环、越级移动、并发完成、父子删除恢复均有单元测试和集成测试。
- 任务任意修改立即在 UI 体现并落库，不等待网络。
- 批量操作可一次撤销，撤销和原操作都正确进入同步队列。

## P0-3：时间、重复任务、提醒与 Windows 外壳

### 目标

把提醒和重复任务从独立工具模块变为真实任务数据的可靠功能，并使桌面端行为符合 Windows 使用场景。

### 执行步骤

1. 在 TaskDetail 中接入多提醒编辑器与重复规则编辑器；任何任务时间修改必须取消旧调度并建立新调度。
2. 完成重复规则：每天、工作日、每周指定星期、每月日期、每年日期、完成后每隔 N 天、开始/结束日期、跳过本次；月末、闰年、夏令时必须有边界测试。
3. 完成任务时在同一事务内生成下一次实例；确保数据库 `source` 枚举、重复规则表和同步 outbox 一致。
4. 提醒调度器从 SQLite 读取真实 reminders，应用启动、网络恢复、系统唤醒、时区变化、系统时间跳变时重新扫描。
5. 实现通知动作：完成、稍后 10 分钟、稍后 1 小时、明天；通知点击打开应用并定位任务。
6. 实现安静时段策略，普通提醒延后到安静时段结束；重要提醒是否绕过安静时段必须是显式设置。
7. Tauri 侧补齐真实桌面壳：
   - 加入并注册 single-instance 插件；第二次启动唤醒已有窗口；
   - 保存/恢复窗口大小、位置、最大化状态，并处理双屏不可见位置；
   - 关闭按钮默认隐藏到托盘，真实退出时给出提醒中断确认；
   - 托盘菜单的快速添加、今天、同步、设置、退出全部调用真实应用命令；
   - `Ctrl+N`、`Ctrl+K`、`Ctrl+Enter`、`Esc` 必须对应真实 UI 行为；全局快捷键失败时可重新配置；
   - 补齐 `src-tauri/icons` 下实际图标并验证 NSIS/MSI 资源路径。

### 验收标准

- 主窗口隐藏到托盘后，真实任务的提醒仍可弹出且不重复。
- 睡眠越过提醒时间后，唤醒时能扫描并展示错过提醒。
- 100%、125%、150%、200% DPI，单屏/双屏，中文路径 Windows 用户下均通过手工验证。

## P0-4：服务端、认证、同步与部署安全

### 目标

建立可恢复、可幂等、可冲突处理的服务端同步系统，并满足私有部署的安全边界。

### 执行步骤

1. 为任务、项目、标签、任务标签、提醒、重复规则、AI capture 建立服务端 SQLAlchemy 模型与 Alembic revision；禁止继续依赖 `Base.metadata.create_all()` 作为生产迁移机制。
2. 增加管理员初始化命令或受控初始化流程，用于创建首位用户；不开放公开注册。
3. 认证规则：Argon2id 哈希密码，短期 Access Token，Refresh Token 只保存哈希；刷新必须轮换 Refresh Token，并可按设备撤销。
4. 客户端 Token 必须存入系统安全凭据存储，禁止写入 `.env`、普通配置、localStorage、日志或任务表。
5. 实现并接入 `POST /auth/login`、`/refresh`、`/logout`、`GET /me`、`POST /devices/register`、同步 push/pull、AI parse；所有写接口支持幂等请求 ID 和稳定错误码。
6. 同步操作必须包含 `operation_id`、实体类型、实体 ID、操作类型、基础 revision、payload、创建时间。服务端在一个事务中校验、写入实体、写入事件、推进游标。
7. 同步冲突规则必须书面固定：
   - 普通字段按服务端版本的最后写入胜出；
   - 删除与修改冲突保留可恢复副本，不静默丢失；
   - 父子关系变化重新验证 3 级和无环；
   - 无法自动合并时生成 conflict copy，由 UI 选择版本；
   - 冲突解决动作本身再次同步。
8. 删除客户端 `sync.ts` 中含 `...` 的占位 SQL，并完整实现 task/project/tag/reminder/recurrence 的远端应用。远端应用必须幂等。
9. 部署安全：
   - PostgreSQL 不发布到公网；仅 API 所在 Docker 网络访问；
   - 生产 Caddy 使用实际域名和自动 HTTPS，不得只监听 `:80`；
   - 删除所有生产默认密码、默认 JWT Secret 与可预测回退；启动时检测空值/占位值并拒绝生产启动；
   - CORS 只允许必要来源、方法和请求头；登录、AI、导入接口增加速率与体积限制；
   - API healthcheck 使用容器内确实可用的工具，并将数据库连通性使用 `/ready` 验证；
   - 每日备份、保留周期、恢复演练和磁盘告警必须可执行。
10. Tauri capability 采用最小权限：限定文件选择/导入导出目录，移除广泛的 `fs:default`、无范围写权限和不需要的 shell 能力。

### 验收标准

- 两台设备在离线状态下分别创建、同时修改、删除与修改、父子任务冲突、响应丢失重试、断点拉取均有集成测试。
- 同一 `operation_id` 重放不会创建重复任务。
- 数据库恢复演练后可登录、可同步、可读取历史数据；演练记录归档。
- 生产 compose 配置不暴露 5432，HTTPS 与健康检查实际可用。

## P0-5：把 AI 解析改为真实、受控、可解释的流程

### 目标

用服务端 Provider 和严格结构校验替代活动页面中的本地关键词模拟，实现“AI 可用时增强、不可用时普通 Todo 不受影响”。

### 执行步骤

1. UI 只通过已认证 API 调用 AI 解析；使用统一 API Base 配置，禁止写死 `localhost` 或遗漏 Authorization Header。
2. 统一前后端字段命名映射，确认卡接收的数据必须与 API 响应的契约测试一致。
3. 保留 `TaskParserProvider` 接口，并将确定性规则与模型调用改为可控策略：
   - 明确日期、时间、重复规则可由确定性规则提供高可信字段；
   - “有标题”本身不得将整体结果判为 high；
   - 确定性规则无法覆盖的语义才调用模型；
   - Provider 失败时返回可编辑的低置信结果，保留原文。
4. 服务端在模型输出后做硬校验，不信任 prompt：
   - 最多 20 个任务；最大层级 3，超出自动拍平并加入 warning；
   - 标题非空且长度受限；
   - priority、重复规则、时区、日期、提醒时间均为允许值；
   - 过去日期、冲突日期和无效提醒不能直接建立带提醒任务；
   - 原文仅作为数据，禁止模型指令注入改变系统规则。
5. 置信度规则固定为：
   - `high`：所有必需字段可验证、无不确定字段、无 warning，且符合已冻结的语料指标；
   - `medium/low`：必须显示可编辑确认卡，用户确认后才创建；
   - 自动创建后显示摘要与可撤销入口；撤销必须删除同一次 capture 创建的全部任务；
   - 请求中可取消，重复点击使用客户端请求 ID 防重。
6. 冻结中文语料与指标：明确日期时间准确率不低于 95%，明确重复规则准确率不低于 90%；每次 Provider、提示词或规则改动均跑回归集。
7. 记录 AI 调用耗时、模型、Token、错误码和 capture 状态；默认不记录完整任务正文、原始敏感输入或 API Key。设置页应说明当前服务商、服务器地址、发送范围和关闭 AI 的方式。

### 验收标准

- “明天下午三点交实验报告，提前一天和一小时提醒”“每周一晚上八点复习高数”“月底完成实习报告，分为……”等语料均通过结构断言。
- 提示注入、空输入、过去日期、否定提醒、多个独立任务等边界用例全部通过。
- AI 超时或不可用时，普通创建功能仍可完整使用，原始文本不会丢失。

## P0-6：回收站、导入导出与备份恢复

### 目标

让用户数据可撤销、可迁移、可恢复，并确保父子与同步关系不被破坏。

### 执行步骤

1. 删除默认软删除，显示即时撤销；回收站展示原项目、删除时间、剩余保留天数。
2. 恢复父任务时完整恢复子任务；永久删除必须二次确认，并确认 tombstone 已被活动设备同步后再清理。
3. 30 天清理由后台任务执行，产生可审计日志；不得仅按“最近 N 条”截断。
4. 导入支持 CSV 和本软件完整 JSON：
   - 检测 UTF-8/UTF-8 BOM，不支持编码必须报告；
   - CSV 必须采用标准解析器，不能用字符串 `split/join`；
   - 提供列映射、预览、重复检测、错误报告、批次 ID、取消和整批撤销；
   - 导入在事务或隔离批次中完成，失败不得污染现有数据。
5. 导出完整 JSON（任务、父子、项目、标签、提醒、重复规则、格式版本、创建时间）和通用 CSV；Markdown 为 P1。
6. 备份恢复前自动备份当前库；备份中包含版本与完整性校验；恢复前展示影响范围，恢复后执行一致性检查。

### 验收标准

- 包含父子、标签、提醒、重复规则的数据可完整“导出 -> 清空测试库 -> 导入恢复”。
- 非法日期、循环层级、重复 ID、错误编码能生成清晰错误报告并不破坏原数据。
- 回收站 30 天清理、手动永久删除、恢复与同步 tombstone 各有测试。

## P0-7：测试、性能、打包与发布门禁

### 目标

从“可以编译”提升到“可证明可交付”。

### 测试分层

1. 单元测试：任务 CRUD、父子完成、循环检测、时区转换、重复下一实例、提醒去重/稍后、回收站期限、同步幂等/冲突、AI Schema、CSV/JSON 导入。
2. 集成测试：SQLite migration、FastAPI + PostgreSQL、登录/刷新/撤销、离线 push/pull、AI 超时、导入整批撤销、服务端备份恢复。
3. 端到端测试：首次配置与登录、普通任务完整生命周期、AI 父子创建、断网重启联网同步、托盘提醒、回收站恢复、导出导入恢复。
4. Windows 兼容性：Windows 11；尽力支持 Windows 10 22H2；单/双屏；100%~200% DPI；中英文用户路径；标准用户；睡眠/锁屏/网络切换/时区切换/WebView2 缺失。

### CI 门禁

每个合并请求至少执行：

```text
前端：npm ci -> lint -> tsc -> vitest -> build
后端：锁定依赖安装 -> pytest -> API 契约测试
服务端：Alembic upgrade/downgrade 测试 -> PostgreSQL 集成测试
桌面：Tauri 检查/打包 -> 安装包资源完整性检查
安全：依赖漏洞扫描 -> Secret 扫描 -> compose 配置检查
```

### 发布前强制门禁

1. 所有 P0 在需求矩阵中有“已验证”证据。
2. 无已知数据丢失、重复任务、提醒失效或未解决同步冲突。
3. 完成客户端数据库升级演练、服务端数据库恢复演练、两设备离线冲突演练。
4. AI 不可用时普通 Todo 完整可用。
5. NSIS 或 MSI 在干净 Windows 环境完成全新安装、覆盖安装、卸载、保留/删除数据验证，并生成 SHA-256。
6. 发布说明包含版本号、数据库迁移版本、同步协议版本、已知限制、回滚方式。

## 5. 最终完成定义（本方案执行后的 DoD）

只有同时满足以下条件，EZTODO 才可标记为“PC MVP 已完成”：

- 用户离线可使用全部基础任务功能，重启后数据仍存在。
- 本地修改在同步失败时不丢失；两设备同步不产生重复任务。
- 删除可即时撤销，并能在 30 天内恢复父子任务关系。
- 父子联动无循环、无半完成状态；重复任务在月末、闰年、时区变化下正确。
- 主窗口隐藏到托盘后提醒仍有效，点击通知可定位任务。
- AI 输出通过服务端校验；低置信度需确认；失败不丢失输入。
- 用户可导出完整数据、导入恢复，并完成客户端与服务端恢复演练。
- 所有 P0 测试、CI 门禁、干净 Windows 安装验证全部通过。

在上述条件满足前，项目状态应标记为“开发中 / 不可发布”，而不是“已完成”。
