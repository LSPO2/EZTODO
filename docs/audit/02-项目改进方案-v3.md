# EZTODO 项目改进方案 v3

日期：2026-07-24

## 总体原则

先保证数据不丢、链路真实、失败可见，再扩展功能。所有状态使用“已实现 → 已接线 → 自动化验证 → 真机验证 → 已验收”的单向提升规则。

## P0：发布阻断项

### 1. 修复验收矩阵可信度

- 让 `verify-matrix.js` 从 388 条明细自动计算阶段和总计。
- 校验摘要数字、明细数字、P0 ID 数量三者一致。
- 每条 P0 增加实现链接、测试链接、真机证据、最后验证日期。
- 为 12 条 DoD 单独建立发布看板；任何一条未通过都阻止 MVP 发布。

验收：人工修改任一汇总数字时 CI 必须失败。

### 2. AI 创建改为事务化业务服务

- 新建 `AICaptureService`，职责包括输入长度限制、Schema 校验、最多 20 项、最多 3 层、隐私策略和确认后写入。
- 父任务、子任务、提醒、重复规则、标签关系和同步 outbox 在单个 SQLite 事务中提交。
- 任一写入失败必须全部回滚，并保留原始文字供用户修改/普通创建。
- 创建成功后提供一次性撤销入口。

验收：故意让第 N 个子任务写入失败，数据库任务数、关系和 outbox 均不变化。

### 3. 明确 AI 密钥模式

- 默认模式：EZTODO 服务端代理，客户端不持有模型 Key，符合原清单。
- 可选模式：用户 BYOK；API Base/模型保存在设置表，Key 存 Windows 凭据管理器。
- 两种模式都禁止日志记录 Key、完整输入和完整模型响应。
- 对 BYOK 域名变更、HTTP、重定向、证书错误给出明确提示。

验收：扫描 SQLite、localStorage、日志和导出文件，不得出现测试 Key。

### 4. 完成账号与同步闭环

- 登录、Refresh Token 轮换/撤销、设备注册、安全凭据存储。
- push/pull 幂等、游标、墓碑、冲突策略和失败重试。
- 两设备交叉修改、离线重启、重复提交、时钟偏差测试。

验收：两台独立客户端完成 DoD 的“不重复、不丢失、可恢复”场景。

### 5. Windows 原生验收

- SQLite：真实 Tauri 数据库、升级迁移、备份、崩溃恢复。
- 通知：托盘隐藏、睡眠恢复、点击导航、完成/稍后提醒。
- 外壳：单实例、多屏窗口恢复、DPI、快捷键冲突。
- 发布：安装、升级、卸载、签名、更新失败回滚。

验收：固定 Windows 环境完成脚本和手工清单，并保存截图、版本、日志摘要。

## P1：架构和体验

### 6. 拆分主应用

建议结构：

```text
src/
  pages/
    tasks-page.tsx
    ai-create-page.tsx
    settings-page.tsx
    data-page.tsx
  components/
  features/
    ai/
    tasks/
    sync/
    reminders/
  services/
  stores/
```

- 页面只负责组合组件。
- 网络调用、Schema 校验、事务写入和通知放入服务层。
- 将内联样式迁到 CSS Modules 或统一 token，提升可访问性和响应式布局。

### 7. 统一共享协议

- AI、任务、提醒、重复和同步响应使用共享 JSON Schema。
- FastAPI 响应与 TypeScript 类型从同一 Schema 生成或运行时校验。
- 禁止在边界处使用未校验的 `response.json()`。

### 8. 清理技术债

- 删除或迁移未接入的旧 AI 组件，消除重复实现。
- 先清理新改文件 warning，再按 `database → import/export → sync → UI` 清零约 70 个 warning。
- 增加 UTF-8/mojibake 扫描和敏感信息扫描。
- 修复动态 import 被静态 import 抵消的构建警告，确保 SQLite 代码只在 Tauri 路径加载。

## P2：产品增强

- AI 模板、默认项目/标签、预估时长和用户词典。
- 保存常用过滤器、键盘无障碍、命令面板。
- 可观测性仅记录耗时、状态码、模型名和匿名错误码，不记录任务正文。
- 在 PC MVP 稳定后再评估语音或 Android，不提前扩散平台范围。

## 推荐实施顺序

1. 需求矩阵与 DoD 门禁。
2. AI 事务化、密钥模式和真实 API 验收。
3. 登录/设备/同步。
4. 提醒和 Windows 真机验收。
5. 备份恢复、安装升级发布。
6. 主应用拆分与 warning/乱码清理。
7. P2 产品增强。
