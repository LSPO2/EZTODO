## 1. 用户与账号规则

### R-001 单用户模式
- **规则**：首版只支持单用户，服务端暂不开放注册
- **原因**：简化首版开发，聚焦核心功能
- **影响**：服务端不需要注册接口，只需登录接口

### R-002 登录方式
- **规则**：登录方式为服务器地址 + 用户名 + 密码
- **流程**：
  1. 用户输入服务器地址（如 `https://eztodo.example.com`）
  2. 输入用户名和密码
  3. 客户端调用 `POST /api/v1/auth/login`
  4. 服务端返回 Access Token 和 Refresh Token
- **安全要求**：
  - 密码使用 Argon2id 哈希存储
  - Token 不写入明文配置文件
  - 登录接口增加速率限制

## 2. 任务规则

### R-003 任务层级
- **规则**：任务层级最多 3 级（任务 → 子任务 → 孙任务）
- **约束**：
  - 禁止把任务移动到自己的子孙任务下面（防止循环）
  - 父任务删除时，子任务一起进入回收站
- **UI 表现**：
  - 子任务缩进显示
  - 支持折叠/展开
  - 显示父任务完成进度（如 `3/5`）

### R-004 时区规则
- **规则**：默认时区跟随 Windows 系统
- **实现**：
  - 创建任务时记录当前时区（IANA 格式，如 `Asia/Shanghai`）
  - 所有精确时间保存为 UTC
  - 全天任务按本地日期存储（独立日期字段，不用 UTC 零点）
- **边界情况**：
  - 系统时区改变后重新计算未来提醒
  - 夏令时切换时正确处理时间

### R-005 时间字段分离
- **规则**：日期、截止时间和提醒时间是不同字段
- **字段说明**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `scheduledDate` | `string (YYYY-MM-DD)` | 全天任务的计划日期 |
| `scheduledAt` | `string (ISO 8601 UTC)` | 有具体时间的计划时间 |
| `dueAt` | `string (ISO 8601 UTC)` | 截止时间 |
| `remindAt` | `string (ISO 8601 UTC)` | 提醒时间（可多个） |
| `isAllDay` | `boolean` | 是否全天任务 |

### R-006 无时间任务提醒
- **规则**：无时间任务默认不推送，除非用户设置默认提醒规则
- **用户设置**：
  - 可配置"无时间任务默认提醒"（如：创建后 1 天提醒）
  - 该设置保存在 `settings` 表

## 3. 父子任务规则

### PR-001 自动完成父任务
- **规则**：子任务全部完成时，自动完成父任务
- **实现**：在单个数据库事务内检查并执行

### PR-002 完成父任务确认
- **规则**：父任务仍有未完成子任务时，完成父任务必须弹出确认
- **确认框选项**：
  - "仅完成父任务" - 只完成父任务，子任务保持原状
  - "同时完成所有子任务" - 完成父任务和所有子任务

### PR-003 重新打开父任务
- **规则**：重新打开父任务时，允许选择是否恢复子任务
- **确认框选项**：
  - "仅恢复父任务" - 只恢复父任务
  - "同时恢复所有子任务" - 恢复父任务和所有子任务

### PR-004 循环引用检测
- **规则**：禁止把任务移动到自己的子孙任务下面
- **实现**：移动前遍历目标位置的所有祖先，检查是否包含当前任务

### PR-005 级联删除
- **规则**：父任务删除时，其子任务一起进入回收站
- **恢复**：恢复父任务时，一并恢复其子任务

### PR-006 子任务截止时间警告（P1）
- **规则**：子任务截止时间晚于父任务时给出警告，但不强制阻止
- **UI**：显示黄色警告图标，提示"子任务截止时间晚于父任务"

## 4. 回收站规则

### R-007 回收站保留期
- **规则**：回收站按时间保留 30 天
- **清理逻辑**：
  - 每天后台检查超过 30 天的已删除任务
  - 清理前确保删除墓碑已同步到服务器
  - 物理清理前确认所有活动设备已收到删除事件

## 5. AI 解析规则

### R-008 高置信度自动创建
- **规则**：AI 高置信度结果自动建立，低置信度结果要求确认
- **置信度定义**：

| 级别 | 行为 | 示例 |
|---|---|---|
| 高 | 自动创建，显示撤销按钮 | "明天下午3点开会" |
| 中 | 显示确认卡片 | "下周交报告" |
| 低 | 必须手动确认 | "有空整理桌面" |

### R-009 AI 撤销入口
- **规则**：AI 自动创建后提供明显的撤销入口
- **UI**：
  - 创建成功后显示 Toast 通知
  - 通知包含"撤销"按钮
  - 撤销后恢复到 AI 确认卡片状态

### R-010 保存 AI 原始输入（P1）
- **规则**：保存 AI 原始输入和解析结果
- **用途**：用于调试和改进 AI 解析
- **存储**：`ai_captures` 表

### R-011 语音音频处理（P1）
- **规则**：语音原始音频在转写完成后立即删除
- **原因**：隐私保护，不存储用户语音数据

## 6. 数据完整性规则

### 标题规则
- 标题去除首尾空白
- 空标题不得保存
- 标题最大长度：500 字符

### 备注规则
- 备注最大长度：10000 字符
- 备注支持纯文本（首版不支持 Markdown）

### 同步规则
- 所有 ID 使用 UUIDv7（客户端生成）
- 时间戳使用 ISO 8601，传输时使用 UTC
- 软删除记录保留同步墓碑
- 未同步前不得物理删除

## 9. MVP 验收场景

### 场景 1：AI 创建任务
```
输入："明天下午三点交实验报告，提前一天和一小时提醒"
预期：
- 创建任务"交实验报告"
- 计划时间：明天 15:00
- 提醒 1：明天 15:00（提前 0）
- 提醒 2：明天 14:00（提前 1 小时）
- 提醒 3：今天 15:00（提前 1 天）
```

### 场景 2：重复任务
```
输入："每周一晚上八点复习高数"
预期：
- 创建任务"复习高数"
- 重复规则：每周一
- 计划时间：周一 20:00
```

### 场景 3：父子任务
```
输入："月底完成实习报告，分为整理照片、写正文、调整格式"
预期：
- 创建父任务"完成实习报告"
- 创建子任务 1："整理照片"
- 创建子任务 2："写正文"
- 创建子任务 3："调整格式"
```

### 场景 4：离线创建
```
操作：断网创建任务，重启软件
预期：任务仍然存在
```

### 场景 5：离线同步
```
操作：恢复网络后
预期：离线任务自动上传服务器
```

### 场景 6：托盘提醒
```
操作：主窗口关闭到托盘后
预期：提醒仍能正常弹出
```

### 场景 7：回收站恢复
```
操作：删除一个包含子任务的项目后，从回收站恢复
预期：父任务和子任务都恢复
```

## 10. 技术约束

### 客户端约束
- UI 不得直接拼接 SQL，统一通过 Repository/Service 层访问数据
- 任务 ID 在客户端生成，离线创建时不依赖服务器
- 所有修改立即写入本地数据库，不依赖服务器响应

### 服务端约束
- AI 服务商封装成 Provider 接口，不能写死在某一家模型上
- 同步协议独立于 Tauri，未来 Android 客户端可以复用
- 服务端时间作为版本排序依据，不信任客户端系统时间

### 共享协议约束
- 时间、重复规则和任务结构定义放入共享协议包
- 客户端和服务端从同一份 Schema 生成或校验类型
- API 增加显式版本（`/api/v1`）
